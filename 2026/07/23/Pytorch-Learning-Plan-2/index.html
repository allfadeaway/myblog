Pytorch Learning Plan 2-SASRec

本文主要记录复现 SASRec 的过程以及得到的一些经验（参照 前辈的代码），写为 Plan 2 是因为 Plan 1 是复现了 Transformer （参照 CS336 的assignment）但是还没写总结。

按照我目前学习深度学习的经验，其过程可以分为：数据准备、模型（model）、优化（optimizer）、目标（loss）、评估（evaluate），本文也会以这个分类进行展开。

AI给出的更具体的过程

数据：Dataset / DataLoader / 预处理与增强

模型：网络结构、参数初始化

目标：loss + 正则项

梯度：autograd / 反向传播

优化：optimizer + scheduler

循环：training loop、评估、early stopping

工程：checkpoint、日志、device / AMP / 分布式

SASRec 总览

它想解决什么问题

推荐系统里有一类问题叫序列推荐：已知一个用户按时间顺序交互过的物品 [i₁, i₂, ..., iₜ]，预测他下一个会点什么。

在 SASRec 之前，这类问题主流用 RNN/GRU 来建模序列。

SASRec 的做法是把 Transformer 的自注意力搬过来：让模型在预测下一个物品时，自己去决定"历史里哪几个物品最相关"，而不是像 RNN 那样把信息压进一个固定大小的隐状态里逐步传递。

核心思路

用带因果掩码的自注意力，把用户历史编码成"每个位置的表示向量"，再用这个向量和候选物品做点积打分

数据准备

本次实验使用 ml-1m 数据集，其由若干个 “user item” 形式的行组成。

预处理

首先整合每个用户的物品信息，产生 user_items ，表示每个用户访问的物品序列，然后生成训练集、验证集、测试集、用户数量、物品数量（ user_train, user_valid, user_test, usernum, itemnum ）等数据，这里的方法是把 user_items[-2] 作为验证项，把 uesr_items[-1] 作为测试项，其余作为训练项。

sampler

sampler 的作用是产生单一的训练样本，我们需要的格式是 [user_id, seq, pos, neg] 表示用户ID、操作序列、正预测序列、负预测序列。

Example

user_train: [a, b, c], maxlen = 5

seq: [0, 0, 0, a, b]

pos: [0, 0, 0, b, c]

neg: [0, 0, 0, d, e]

collate_fn

collate_fn 的作用是把许多个单一样本组成一个 batch ，对 user_id 随机排序然后用 sampler 采样并合在一起即可。

并行加载

这里使用了 multiprocessing 进行并行。

模型

模型部分没什么特别的，写过 transformer 之后理解这些还是比较容易的。

主要就是实现 __init__() 和 forward() ，SASRec 的 forward 主要需要求出 pos_logits 和 neg_logits ，分别表示 pos 和 neg 序列的打分。

另外添加了 predict() 用于在 eval 时预测下一个物品与 item_indices 中物品的打分

目标

这里主要是对 item_embedding 添加了 L2 正则项，因为物品 embedding 的模长越大，内积越大，打分就越高

loss 采用二分类损失计算。

注意：padding 位置要从 loss 里排除掉。padding 位的分数是凑数算出来的，如果让它们参与损失，模型会被迫去拟合噪声。

优化

直接使用 Adam 优化器。

评估

使用 HT 和 NDCG 两种评估标准，没啥好说的。

反思

为什么这里的 FFN 不需要像 transformer 一样把隐藏层提高到例如 d_model * 4？

opinion

可能是比较 empiricism 的东西，AI给出的解答如下：

真正的差异在于：前馈层在两个任务里承担的角色不一样。

在语言模型里，前馈层被认为存储了大量知识和模式——有研究把它类比成"键值记忆库"，模型对世界的了解很大程度上压在这些矩阵里。所以它需要很宽，宽度直接换来容量。

而序列推荐更接近一个匹配任务：核心问题是"这个用户当前状态，和哪些物品向量最接近"。这里的知识主要存在物品嵌入表里（哪些物品相似、哪些常一起出现），前馈层只是给序列表示做一次非线性变换，任务轻得多。重头戏不在前馈，在嵌入表和注意力。

其次是规模和数据的匹配。

SASRec 的 d=50，本来就是个很小的模型。而推荐数据是隐式反馈、高度稀疏——一个用户看过几百部电影，相对 3416 个物品是极稀疏的，信号也弱（点击不等于喜欢）。这种数据喂不动太大的容量，加宽很容易变成拟合噪声。作者配的 dropout=0.2 已经是挺强的正则了,说明他们本来就在压过拟合。

为什么模型在做 item_embedding 的时候要 seqs *= self.item_embed.embedding_dim ** 0.5？

opinion

为了保证物品嵌入和位置嵌入的量级匹配

要注意 mask 和 padding，这是 SASRec 中特别容易踩坑的地方

复现的一些心得
当前也是复现完了 Transformer 和 SASRec，有一些基本的体会： 复现的过程中会发现很多之前理解上有漏洞的地方，这些地方是尤其需要注意的：例如 SASRec 隐藏层的问题等。 复现的关键不在于写代码，AI 时代写代码变得很不值钱，更重要的是理解代码的意思，知道某一个问题需要用什么办法去解决。 复现的时候需要注意数据的形状，这能很好地帮助理解。 注意调试方法的积累，学会怎么修改、调试代码，做好阶段性测试。 积累模块的思维，就像是算法或者数据结构一样，了解一个模块的作用、输入输出等等，设计新东西的时候整块取用即可。 （后面在看别人代码的时候可以积累一些好的实现方法、代码习惯等等） 后续会复现 TIGER，后面可能会继续搞 DPO、GRPO 之类的东西。
